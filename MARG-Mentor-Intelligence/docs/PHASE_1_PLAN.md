## 1. Goal and scope

**Goal:** a secure, testable foundation that boots in mock mode, with a passing test suite that needs no external services, and verified connectivity to the engine's own PostgreSQL database.

### In scope
1. Project tooling (uv, `pyproject.toml`, lockfile, ruff, mypy, pytest)
2. Settings with startup validation, secret handling and the `marg_db` guard
3. Structured JSON logging with redaction and request/execution context
4. Pydantic schemas: canonical status enums, proposal status, common types, event envelope, execution, LLM contracts, engine-side views of backend entities
5. Engine database: async SQLAlchemy, five foundation tables, Alembic (async) with the first migration
6. Provider layer: `LLMProvider` port, `AnthropicProvider`, disabled provider, `SingleModelRouter`, usage tracker, prompt registry
7. Provisional RBAC configuration loader (placeholder roles only)
8. Backend adapter port + **development-only** `MockBackendAdapter` + labelled mock dataset. The MARG HTTP adapter stays blocked.
9. `BaseAgent` template, `AgentContext`, `AgentResult`
10. FastAPI app with `/health/live` and `/health/ready`
11. Unit, integration and safety tests for all of the above

### Out of scope (later phases)
Event bus, orchestrator, policy and approval engines, tool registry (Phase 2) · any operational agent (Phases 3–4) · Redis, ARQ, cron (Phase 5) · proposals, approvals, notifications and memory tables (Phase 2+) · real MARG integration (Phase 8, blocked).

## 4. Database setup

### 4.1 Design
- Database `marg_mentor_intelligence` only. Application schema `mie`, test schema `mie_test`.
- Login role `marg_mie_app`: not a superuser, cannot create databases or roles, and owns only `mie` and `mie_test`.
- The connection sets `search_path` to the configured schema (asyncpg `server_settings`). Models have no hardcoded schema.
- **Guards (TD-18):** `DB_NAME` checked against `DB_FORBIDDEN_NAMES` before connecting. After connecting, `current_database()` and `current_schema()` are verified. Alembic applies the same checks.

### 4.2 One-time role and schema creation (owner runs, after approval)

Open psql as the `postgres` superuser, **connected to the new database**:

```powershell
& "D:\postgre\bin\psql.exe" -U postgres -h localhost -p 5432 -d marg_mentor_intelligence
```

Then, inside psql:

```sql
-- Confirm you are in the right database before running anything else:
SELECT current_database();   -- must print: marg_mentor_intelligence

CREATE ROLE marg_mie_app LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION;
\password marg_mie_app
-- (type the new password twice; it is not echoed or stored in shell history)

GRANT CONNECT, TEMPORARY ON DATABASE marg_mentor_intelligence TO marg_mie_app;
CREATE SCHEMA mie      AUTHORIZATION marg_mie_app;
CREATE SCHEMA mie_test AUTHORIZATION marg_mie_app;
ALTER ROLE marg_mie_app IN DATABASE marg_mentor_intelligence SET search_path = mie;
\q
```

None of these statements touches `marg_db`.

> Note: PostgreSQL grants `CONNECT` on every database to `PUBLIC` by default, so the new role could *connect* to `marg_db`. It has no table privileges there unless they were granted to `PUBLIC`. Revoking that would change `marg_db`'s permissions, which is outside this project's authority, so it is left as a decision for whoever administers `marg_db`. The engine's own guards prevent it from ever connecting there.

Verify the role works:

```powershell
& "D:\postgre\bin\psql.exe" -U marg_mie_app -h localhost -p 5432 -d marg_mentor_intelligence -c "SELECT current_database(), current_user, current_schema();"
# expected: marg_mentor_intelligence | marg_mie_app | mie
```

## 6. Configuration (`app/config.py`)

`Settings(BaseSettings)` reads environment variables, then `.env`. Real environment variables win, so the existing user-level `ANTHROPIC_API_KEY` is used without being copied into `.env`.

Startup validation rules (each has a test):

| Rule | Failure |
|---|---|
| `AI_ENABLED=true` requires a non-empty `ANTHROPIC_API_KEY` and `ANTHROPIC_MODEL` | startup error naming the missing variable (never its value) |
| No model ID default exists in code | — |
| `BACKEND_MODE=marg` | **refused in Phase 1:** "MARG backend integration is not authorised until the OpenAPI compatibility audit" |
| `DEV_AUTH_HEADER_ENABLED=true` with `APP_ENV` in {staging, production} or with `BACKEND_MODE=marg` | startup error |
| `DB_NAME` in `DB_FORBIDDEN_NAMES` (case-insensitive) | startup error |
| `DEFAULT_TIMEZONE` not a valid IANA zone | startup error |
| `LLM_PRICING` malformed | startup error. A missing entry for the model is allowed and reported as "not configured". |
| `ANTHROPIC_EFFORT` set to an unknown level | startup error |
| `PSEUDONYMISATION_KEY` empty outside `APP_ENV=test`, or shorter than 32 characters | startup error |
| `RBAC_CONFIG_PATH` missing, unparsable, or references unknown permissions | startup error |

All secrets are `SecretStr`. `Settings.__repr__`, `model_dump()` and health output never contain secret values. A `describe()` method returns a safe summary (for example, `{"anthropic_api_key": "configured"}`).

## 7. Claude provider setup

### 7.1 Interfaces
```python
class LLMProvider(Protocol):
    async def generate_structured(self, request: LLMRequest, output_model: type[T]) -> LLMResult[T]: ...
    async def generate_text(self, request: LLMRequest) -> LLMResult[str]: ...

class ModelRouter(Protocol):
    def select_model(self, hint: ComplexityHint) -> str: ...

class SingleModelRouter:          # Phase 1: always returns settings.anthropic_model
```
`LLMRequest`: `prompt_id`, `prompt_version`, `data_sections` (untrusted, wrapped by the registry), `instructions`, `max_output_tokens`, `complexity_hint`, `trace` (execution_id, correlation_id, mentor token).
`LLMResult`: `output`, `model_requested`, `model_served`, `stop_reason`, `usage` (input/output/cache-read/cache-creation tokens), `cost_usd | None`, `provider_request_id`, `latency_ms`.

### 7.2 `AnthropicProvider` behaviour
1. **Budget check** (usage tracker): if the per-mentor or global daily token budget is exhausted, raise `LLMBudgetExceededError`. No request is made.
2. **Client:** `AsyncAnthropic(api_key=<SecretStr value>, timeout=ANTHROPIC_TIMEOUT_SECONDS, max_retries=ANTHROPIC_MAX_RETRIES)`, created once per process.
3. **Request:** `system` = shared preamble + agent prompt as text blocks, with `cache_control: {"type": "ephemeral"}` on the last system block (stable prefix, nothing time-varying). `messages` = one user turn containing the wrapped data sections and the task instruction. `output_format=<Pydantic model>` via `messages.parse`. `output_config.effort` only if configured. **Never sent:** `temperature`, `top_p`, `top_k`, assistant prefill, forced `tool_choice`.
4. **Refusal fallback** when `ANTHROPIC_REFUSAL_FALLBACK=default`: beta namespace, `betas=["server-side-fallback-2026-07-01"]`, `fallbacks="default"`. Verification item: confirm `client.beta.messages.parse` accepts these with the locked SDK version. Otherwise use `beta.messages.create` + `output_config.format` + our own validation.
5. **Response handling, in order:** `stop_reason == "refusal"` → `LLMRefusalError(category)`. `"max_tokens"` → `LLMTruncatedError`. `parsed_output is None` or our re-validation fails → `LLMOutputInvalidError` (the raw text is kept only in a size-limited debug field and never logged at INFO).
6. **Error mapping** (most specific first): `RateLimitError`, `APITimeoutError`, `APIConnectionError`, `InternalServerError`/5xx → `LLMTransientError`. `AuthenticationError`, `PermissionDeniedError`, `NotFoundError`, `BadRequestError`, `UnprocessableEntityError` → `LLMPermanentError`. Transport retries are the SDK's own (honours `retry-after`). The provider adds no retry loop, and permanent errors are never retried.
7. **Usage:** one `llm_usage` row per attempt that reached the API, including refusals and invalid outputs, with `provider_request_id` from `response._request_id`.
8. **Logging:** model, prompt id/version, token counts, latency, outcome and request id. Never the API key, never prompt or data contents at INFO.

### 7.3 Prompt registry and injection defence
- Prompts are Markdown files: `app/prompts/<prompt_id>/<version>.md`. The version is recorded on every call.
- `wrap_untrusted(name, payload)` produces `<marg_data name="…" trust="untrusted">…JSON…</marg_data>`, escaping any `</marg_data` inside the content.
- The shared preamble states that content inside `marg_data` is data, never instructions. It also sets the content rules: no clinical or psychological judgements, no invented data, report missing data, and AI output is labelled as suggestions.

### 7.4 Disabled provider
When `AI_ENABLED=false`, `DisabledProvider` raises `LLMDisabledError`. `BaseAgent` turns this into a deterministic-only result with `llm_used=false` and a note.

## 8. Mock backend, BaseAgent and RBAC

### 8.1 `MARGBackendAdapter` port (read operations only in Phase 1)
`get_tasks(filters)`, `get_task(task_ref)`, `get_schedule(mentor_ref, window)`, `get_followups(filters)`, `get_school_details(school_ref)`, `get_school_visit_history(school_ref)`. Every call takes the `Principal`. Results use engine-side schemas with `data_source`. Write operations are designed in Phase 2 together with the approval engine.

### 8.2 `MockBackendAdapter`: DEVELOPMENT ONLY
- The module docstring, class name, log line at startup ("MOCK BACKEND ACTIVE — development data only") and `data_source="mock"` on every record all mark it as mock.
- Synthetic dataset: 2 tenants (`mock-tenant-a`, `mock-tenant-b`), 3 mentors, ~4 schools ("Mock School 01"), ~6 teachers ("Mock Teacher 01"), ~15 tasks, visits, follow-ups across all canonical statuses, and a schedule containing one deliberate conflict.
- Dates are generated relative to the injected clock, so tests are deterministic.
- Some tasks deliberately **lack** urgency/impact/risk values to exercise the missing-factor path.
- Tenant/mentor isolation is enforced. Requesting another mentor's data without permission raises `PermissionDenied`.

### 8.3 `marg_backend/` placeholder
`client.py` defines `HttpMARGBackendAdapter`, whose constructor raises `BackendIntegrationNotAuthorised`. There are no endpoints, payload fields or auth formats.

### 8.4 `BaseAgent`
Implements the template from AGENT_DESIGN §1.1: input validation → `analyse` → `needs_llm` + budget → `reason` (one repair attempt on invalid output, then deterministic fallback) → `assemble` → output validation → `allowed_tools` enforcement on proposed actions → step logging. Phase 1 tests it with a small test-only agent. No operational agents are built.

### 8.5 RBAC (provisional)
`config/rbac.dev.toml` maps **placeholder** roles (`dev_mentor`, `dev_supervisor`) to engine permissions (`plan.read`, `proposal.approve`, `mentor_data.read_other`, …). The header of the file says it is provisional and will be replaced after the MARG audit. Unknown roles get no permissions.

## 9. Testing strategy

| Command | What runs | Needs |
|---|---|---|
| `uv run pytest` | unit + integration (SQLite, mock transport) + safety | nothing external |
| `uv run pytest -m postgres` | PostgreSQL integration in schema `mie_test` | P2, P3 |
| `RUN_LIVE_LLM_TESTS=1` + `-m live_llm` | one tiny real Claude call (optional, costs a few tokens) | API key, model |

Markers `postgres` and `live_llm` are skipped automatically unless explicitly selected and configured.
